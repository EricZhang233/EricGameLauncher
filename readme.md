## 亮点速览

*   🧩 **全链路执行**：主程序、管理器、代替启动、伴随执行四条链路逐项可配；EXE、快捷方式、URL 协议、网页、商店应用都能直接跑。
*   🖱️ **动态右键菜单**：菜单项随项目自动增减，识别到平台即显示「运行 Steam / 运行 Xbox」；每个项目最多 10 个自定义项，可独立配置标题、命令、参数与提权。
*   🗂️ **多平台一站收纳**：Steam、Epic Games、Xbox、Google Play Games、WeGame、独立 exe、网页与商店应用共处一库，顺序完全自定义。
*   🔍 **多路搜索**：拼音全拼、拼音首字母、中文、英文、路径与 URL 协议都能当关键词——`yxlm` 直达英雄联盟，`C:\Program Files` 按路径命中，`steam` 顺协议捞出全部。
*   📥 **扫描即入库**：自动识别 Steam、Epic Games、Xbox、Google Play Games 与 WeGame 已安装游戏，按新增 / 已存在 / 已失效分组，一键导入或批量清理。
*   📦 **安装或解压**：同一个 EXE 安装包可选择正式安装或仅解压。安装版提供 Windows 卸载入口，解压版可自行管理快捷方式，并在可写位置使用便携数据模式。
*   💻 **CLI & Skill**：命令行与桌面端共用游戏库、设置和核心服务，内置帮助与接入指南，方便脚本与 AI Agent 管理和启动游戏。
*   🚀 **快速启动**：后台宿主预读配置、预热图标与界面，再次打开几乎瞬间出现；默认关闭，可通过“更多 → 退出”结束本次运行。
*   🗑️ **三段式删除**：主界面删除只进回收站，回收站删除才开始 72 小时倒计时，到期后下次启动自动清理——手滑也救得回来。
*   🎒 **配置备份与迁移**：将设置、游戏库、回收站和图标导出为 ZIP，恢复时可选择覆盖或去重添加。安装版使用系统数据，可写目录中的解压版支持系统与便携数据模式切换。

<a name="quickstart"></a>

## 快速开始

*   需要 Windows 11 24H2 或更高版本，支持 x64 和 ARM64 电脑。
*   运行前请安装 x64 版本的 [.NET 10 运行时](https://dotnet.microsoft.com/en-us/download/dotnet/10.0) 和 [Windows App Runtime 1.8](https://learn.microsoft.com/windows/apps/windows-app-sdk/downloads)。
*   ARM64 电脑使用同一套 x64 程序，通过 Windows 11 的 x64 模拟运行；运行依赖也请选择 x64 版本。安装器不会自动安装这些依赖。

### 三步上手

1. **下载**：从 [Releases](https://github.com/EricZhang233/EricGameLauncher/releases/latest) 获取名称为 `EricGameLauncher_Setup_版本号.exe` 的安装包。
2. **部署并运行**：打开 Setup EXE，选择“安装”或“解压”，完成后启动 `EricGameLauncher.exe`。需要配置随目录携带时，按下方[安装指南](#installation)启用便携数据模式。
3. **入库**：点右上角 **更多 → 扫描** 自动识别本机游戏并一键导入，或用 **更多 → 添加** 手动指定 exe、快捷方式、网页、商店应用。

<a name="installation"></a>

## 安装指南

同一个 Setup EXE 提供“安装”和“解压”两个入口，按程序与数据的管理方式选择即可。两种方式运行应用时都需要上方列出的 x64 运行依赖，安装器不会自动安装这些依赖。

### 选择部署方式

| 方式 | 首页入口 | 数据位置 |
| :--- | :--- | :--- |
| **安装模式** | “安装” | 固定使用系统数据目录。 |
| **便携部署** | “解压” | 可写位置支持便携数据模式，配置存放于程序目录的 `Data` 中。 |

### 安装模式

1. 打开 Setup EXE，在首页选择“安装”。
2. 选择安装目录。默认位置为 `%LocalAppData%\Programs\EricSoft\EricGameLauncher`，也可自选目录，路径可包含中文或空格。
3. 确认快捷方式选项：开始菜单快捷方式为必选，桌面快捷方式按需勾选，默认不勾选。
4. 检查确认页后开始安装，完成后通过结果页、开始菜单或桌面入口启动应用。

安装模式固定将设置、游戏库、回收站和图标存放于 `%ProgramData%\eric\EricGameLauncher`，不提供便携数据模式切换。快捷方式由安装器统一维护，因此应用内隐藏快捷方式管理菜单。再次打开 Setup EXE 时会识别已有安装，并显示升级确认页。

### 便携模式部署

1. 打开同一个 Setup EXE，在首页选择“解压”。
2. 选择自己可写的程序目录，例如 `%USERPROFILE%\Apps\EricGameLauncher`。需要便携数据时，请使用 `Program Files`、`Windows` 等受保护位置以外的目录，并确保程序目录及其中的 `Data` 目录可写。
3. 确认路径并开始解压。完成后可在结果页选择启动应用，也可打开目标目录，双击 `EricGameLauncher.exe`。
4. 打开 **设置 → 数据**，查看当前存储模式。如果显示“系统模式”，使用旁边的切换按钮改为“便携模式”，等待配置与图标迁移完成。确认当前数据位置指向程序目录的 `Data` 文件夹。
5. 如需桌面或开始菜单入口，可通过应用内“快捷方式”菜单创建。

**“解压”负责部署程序文件，“便携模式”决定数据保存位置。** 首次使用且没有已有配置时，默认使用系统模式。在支持便携数据的目录中，已有副本沿用所选模式；未设置模式但 `Data` 中已有配置时，会自动读取该配置。需要配置随目录携带时，应完成第 4 步确认。解压过程不登记安装记录、不生成卸载器，也不自动创建快捷方式。

完成便携数据设置后，关闭启动器，即可移动或复制整个程序目录，并保留其中的 `Data` 文件夹。运行依赖仍需在目标电脑安装，游戏路径需与目标电脑上的实际安装位置一致；临时缓存和启动次数不随目录携带。也可以使用[配置备份与恢复](#backup)转移数据。

#### 进阶：将 EXE 改为 ZIP 后直接解压

熟悉文件扩展名与压缩包操作的用户，也可以直接提取 EXE 中的应用文件，无需运行安装器。

1. 复制下载的 `EricGameLauncher_Setup_版本号.exe`。在文件资源管理器中显示文件扩展名，将副本的 `.exe` 后缀改为 `.zip`，例如 `EricGameLauncher_Setup_版本号.zip`。
2. 将改名后的文件作为 ZIP 压缩包打开，把其中全部内容解压到自己可写的程序目录。
3. 运行解压目录中的 `EricGameLauncher.exe`，按上方第 4 步确认并设置便携数据模式；所需的 x64 运行依赖仍需安装。

得到的是用于便携部署的纯应用文件，包含主程序、命令行程序及其依赖，与安装器首页“解压”得到的应用文件相同，**不包含安装器和卸载器**。请完整保留解压内容，不要只复制主程序 EXE；此操作也不会登记安装记录或自动创建快捷方式。

### 更新、迁移与移除

*   **更新安装版**：使用应用内更新，或再次运行 Setup EXE 并选择“升级”。安装目录沿用已有登记，开始菜单及当前实际存在的桌面快捷方式会同步更新。
*   **更新便携副本**：使用应用内更新即可。更新后保持解压部署，数据仍按当前存储模式读取。
*   **改用安装模式**：先在当前解压版中切换为系统数据模式并确认迁移完成，再运行 Setup EXE 安装；也可先导出配置备份，再在安装版中导入。
*   **卸载安装版**：从 **Windows 设置 → 应用 → 已安装的应用** 卸载，或运行安装目录中的 `Uninstall.exe`。默认清理固定系统数据目录；需要保留设置、项目和图标时，勾选“保留数据”，成功后会显示数据位置。
*   **移除便携副本**：先移除应用内创建的快捷方式，关闭快速启动并退出程序，再删除该副本的程序目录。便携数据位于其中的 `Data` 文件夹，需保留时可先导出备份；使用系统模式的数据位于系统数据目录，不随程序目录删除。

卸载安装版时只处理本次安装拥有的程序文件、对应快捷方式、安装记录及所选的数据处理范围。游戏本体、安装目录中的其他文件和其他解压目录的 `Data` 文件夹保留。系统数据目录由使用该位置的副本共享，保留或清理的选择作用于这份共享数据。

### 一屏收纳你的全部游戏

*   **不分平台**：Steam、Epic Games、Xbox、Google Play Games、WeGame、独立 exe、网页链接、商店应用共用一个网格，顺序完全由你决定。
*   **图标可大可小**：从紧凑列表到沉浸大图连续可调，滑块即时生效，下次启动依旧保留。
*   **多路匹配**：`yxlm`（首字母）、`yingxionglianmeng`（全拼）、`部落`（中文）、`pcl`（路径）都能命中。
*   **手动排序**：直接在网格内拖动卡片，松开后保存顺序；拖动期间暂停名称悬停提示。
*   **悬停补全信息**：指针停留片刻即显示完整标题，长名字不必再猜。
*   **启动方式可选**：单击或双击启动，在设置里随时切换。

### 全链路执行：不止是快捷方式

配置一个游戏，等于配置一条完整的启动链路：

| 能力 | 说明 |
| :--- | :--- |
| **主程序** | 原生 `EXE`、`LNK` 快捷方式、`steam://` / `epic://` / `starward://` 等 URL 协议、网页链接、`shell:AppsFolder\` 商店应用，都可以作为启动目标。 |
| **以管理员身份运行** | 各执行目标可分别配置管理员权限，按对应程序的需求选择。 |
| **管理器** | 指定平台管理器路径，或使用已识别的平台入口，从右键菜单单独打开。 |
| **代替主程序启动** | 用自定义命令（例如 `starward://`）完全接管原始 EXE 的启动逻辑。 |
| **启动时同时执行** | 翻译器、计时器、性能监控、按键映射随游戏一起启动，一键双开。 |
| **自定义右键菜单** | 单个项目最多 10 个自定义项，标题、命令、参数、是否提权各自独立；删掉中间项后自动补位。 |
| **参数与环境变量** | 所有执行目标都支持完整参数；`%AppData%`、`%LocalAppData%` 自动展开；属性面板提供独立的路径和参数编辑位置。 |

### 属性面板：每个细节都能改

*   **名称与图标**：随时改名，也可以上传自己的图片当封面。
*   **四类执行目标分栏**：主程序、管理器、代替启动、伴随执行各自独立成行，都带文件选择与参数拆分。
*   **自定义菜单可视化编辑**：标题、命令、提权开关一列排开，最多 10 组。
*   **保存即刻生效**：确认后立即写回本地配置，界面同步刷新；可将客户端标记为游戏平台，并设置是否固定到任务栏快捷列表。

### 一键扫描多个平台

| 平台 | 自动扫描支持 |
| :--- | :--- |
| Steam | 读取本机游戏库与安装清单，支持多个库目录。 |
| Epic Games | 读取本机安装记录，生成对应的平台启动入口。 |
| Xbox / Microsoft Store | 从已安装的商店应用中识别游戏。 |
| Google Play Games | 读取当前用户的本机游戏库，过滤 Google 和 Android 内部组件；有匹配的开始菜单快捷方式时沿用其启动地址。 |
| WeGame | 根据当前用户安装记录发现游戏与启动入口；主列表已有同一游戏目录内的其他启动程序时，按已存在项目处理。 |

其他平台的游戏也可以通过 **更多 → 添加** 手动收录，使用程序、快捷方式或对应客户端已注册的协议地址启动。

*   **自动发现**：原生识别 Steam、Epic Games、Xbox（Microsoft Store / UWP）、Google Play Games 与 WeGame已安装游戏，提取路径并抓取图标。
*   **结果分组**：扫描结果按 **新增 / 已存在 / 已失效** 三组列出，已入库的项目不会重复导入。
*   **一键导入**：全选或逐项勾选后入库。
*   **失效清理**：已卸载或路径失效的项目集中呈现，支持批量删除。

### 任务栏直达平台与常用游戏

右键任务栏上的启动器图标，即可启动固定平台或常用游戏。固定平台沿用主界面顺序，常用项目优先显示手动固定项，其余按成功启动次数排列。在属性面板调整固定状态并保存后，列表会在后台刷新。

### 三段式删除：手滑也能救回来

| 阶段 | 行为 |
| :--- | :--- |
| 第一段 | 主界面删除 → 只移入回收站，游戏还在，随时可以还原。 |
| 第二段 | 回收站中删除 → 进入 72 小时倒计时，界面显示剩余时间。 |
| 第三段 | 倒计时结束 → 下次启动时自动彻底清理。 |

除了逐项还原和删除，回收站也支持一键清空，清空后同样保留 72 小时。还原时若主列表已存在相同路径或项目 ID，会提示冲突。

### 配置备份与恢复

在 **设置 → 数据** 区点击配置导入导出图标，即可在同一个窗口中完成备份、恢复和结果查看。安装版、解压版以及两种数据模式都可使用。

*   **导出 ZIP**：自行选择文件名和保存位置，备份设置、主列表、回收站及引用图标，包括自定义应用图标。游戏文件、临时缓存和启动次数不包含在备份中；找不到的图标会提示缺失数量，其余配置仍可导出。
*   **识别备份**：导入前检查备份格式、配置内容和图标完整性，展示文件名、备份规则与配置版本、生成程序版本及本地生成时间。普通应用发行包不能作为配置备份导入。
*   **选择恢复内容**：可分别勾选“设置”和“项目与图标”，未勾选的内容保留；回收站随“项目与图标”一起恢复。
*   **覆盖或去重添加**：覆盖会替换所选内容；去重添加保留现有设置值并补充缺失字段，按启动目标跳过重复项目，新增项目编号冲突时自动重新分配。完成后显示添加和跳过数量。
*   **恢复保护**：预览后若当前配置被其他进程修改，会要求重新确认；写入失败时尝试恢复原配置，意外中断后在下次访问配置时处理未完成的恢复记录。
*   **跨电脑使用**：备份包含的图标会恢复到当前数据目录。GitHub 令牌保留原 Windows 用户的加密保护，换电脑或账户后可能需要重新填写；游戏启动路径也需与目标电脑上的实际安装位置一致。

### 更新与公告

*   **静默检查更新**：启动时自动查询 GitHub Releases，有新版本时通过版本号与更新图标提示；遇到强制更新会显示更新窗口。
*   **双通道**：**正式版** 只收正式发布，**开发版** 第一时间尝鲜。
*   **一键下载安装**：发现新版本后下载安装，安装版同步维护版本登记与快捷方式，解压版直接更新所在目录的应用文件。更新保留当前部署方式与数据模式；当前版本有可用发行包时，也能执行修复重装。手动检查会立即显示进度。
*   **历史更新记录**：左侧版本列表、右侧完整说明，可跳转到任意版本，内容取自 GitHub 发布记录。
*   **公告中心**：启动时拉取云端公告，正文支持 Markdown、中英双语，已读状态本地持久化，未读带红点提示。
*   **更新保护**：下载完成后先核验 GitHub Asset 的 SHA256，通过才退出并安装；校验失败可重试或关闭更新界面。安装失败会尝试回滚，回滚失败保留备份供恢复。
*   **配置保护**：写入采用原子替换并保留 `.bak`；损坏配置不会被空列表自动覆盖。GUI 与 CLI 的条目修改通过跨进程事务保存。
*   **删除边界**：主列表删除移入回收站，回收站再次删除或清空后保留 72 小时；游戏文件保留在原处。

<a name="settings"></a>

### 设置一览

*   **常规**：快速启动、启动方式（单击 / 双击）、启动后自动退出；动画遵循 Windows 设置。
*   **更新**：更新通道（正式版 / 开发版）、GitHub 令牌（提高 API 限额；令牌以 DPAPI 加密后存于本地）。
*   **数据**：查看数据位置、导入导出配置，并可打开配置目录与缓存目录。可写目录中的解压版支持系统 / 便携数据迁移；安装版及写入受限的解压版固定使用系统数据。
*   **标题栏**：图标大小、回收站、解压版快捷方式管理、隐私与权限说明、检查更新。

将指针移到设置项的图标或名称上可查看说明，点击可展开帮助。

### 快速启动：提前预热，随时打开

*   **后台宿主**：登录后常驻宿主预读配置与条目、校验并重建图标、完整预热一次界面，再把界面释放掉，屏幕上不留任何窗口。
*   **为下次打开做好准备**：宿主保留已预热的资源，再次打开时唤起界面；具体耗时取决于电脑和游戏库。
*   **遵循系统动画**：启动画面遵循 Windows 动画设置，系统关闭动画时直接显示最终状态。
*   **要彻底退出**：**更多 → 退出** 立刻结束界面与后台宿主，且不改动快速启动设置；Windows 11 24H2 及以上也可以在任务栏右键选择「结束任务」。
*   **不想要后台**：关掉开关，自启项随即移除。

<a name="architecture"></a>

## 技术架构

**Eric Game Launcher** 的桌面界面与控制台共用 Core 服务，统一处理配置、游戏库、启动、扫描与更新。

```mermaid
flowchart TB
    subgraph Shell["壳层 · 零业务逻辑"]
        GUI["EricGameLauncher.exe<br/>WinUI 3 渲染 / 动画 / 对话框"]
        CLI["EricGameLauncher.Cli.exe<br/>参数解析 / 输出格式化"]
    end
    subgraph Core["Core · 唯一业务层"]
        SVC["配置与条目服务<br/>启动执行 · 扫描导入<br/>更新公告 · 图标提取"]
    end
    GUI --> SVC
    CLI --> SVC
    SVC --> DATA["settings.yaml · items.yaml · 图标缓存"]
    SVC --> OS["Windows 注册表 / 进程 / 图标 / 协议"]
```

*   **前沿技术栈**：**Windows App SDK 1.8** + **WinUI 3** + **.NET 10**，使用 Mica / 亚克力材质与自适应网格。
*   **单一 Core 原则**：桌面端与命令行共用业务层，功能天然对齐，日志统一记录。
*   **人机皆可读的配置**：YAML（`YamlDotNet`）存储，`settings.yaml` 与 `items.yaml` 分离，高频改动不必重写全部数据。
*   **原生性能**：P/Invoke 调用系统接口完成图标提取与缓存，窗口材质与标题栏交给系统合成。
*   **拼音索引**：`TinyPinyin` 在内存中为标题建立全拼与首字母索引，搜索时直接匹配已有索引。
*   **安全存储**：GitHub 令牌使用 DPAPI 加密后落盘，不写入明文。
*   **独立安装与解压**：无需 MSIX 打包或导入证书，原生 EXE 安装器提供安装与解压两种部署方式。安装器和卸载器不额外依赖 .NET 或 WinUI；应用本体使用系统安装的 x64 .NET Runtime 与 Windows App Runtime。
*   **单实例与快速唤醒**：Win32 单实例与消息唤醒机制保证重复启动不会开出多个窗口，而是直接唤起已有实例。

<a name="faq"></a>

## 常见问题

<details>
<summary><b>为什么登录后任务管理器里会有一个 EricGameLauncher 进程？</b></summary>

这是「快速启动」的后台宿主，用于预读配置与预热界面，让下次打开几乎瞬间完成。快速启动默认关闭。启动器还会向 GitHub 检查更新和获取公告。

不想要的话，在 **设置 → 快速启动** 关闭即可，自启项会被立即移除；也可以随时通过 **更多 → 退出** 结束它。
</details>

<details>
<summary><b>怎么彻底退出，而不是留在后台？</b></summary>

打开 **更多 → 退出**，界面与后台宿主会一起结束，且不会改动快速启动设置。在 Windows 11 24H2 及以上，也可以直接在任务栏右键选择「结束任务」。
</details>

<details>
<summary><b>需要安装吗？会写注册表吗？</b></summary>

可以选择正式安装，也可以仅解压运行。正式安装会登记当前用户的安装信息与卸载入口，并创建所选快捷方式；仅解压不做这些登记。开启快速启动会注册登录自启，解压版还可通过应用内入口管理快捷方式。

游戏扫描会读取本地磁盘和安装记录；识别商店应用类别时，可能向微软查询包系列名称。更新与公告访问 GitHub。
</details>

<details>
<summary><b>我的数据存在哪里？</b></summary>

**系统模式**存放于 `%ProgramData%\eric\EricGameLauncher`：`settings.yaml` 保存设置，`items.yaml` 保存游戏库和回收站，`ico` 保存图标。安装版固定使用此位置，使用同一系统数据目录的副本共享这份数据。

**便携模式**将数据放在程序目录的 `Data` 文件夹中。程序与数据目录可写、且未处于 `Program Files` 或 Windows 等受保护位置的解压版，可在系统与便携模式间切换，切换时迁移配置和图标；写入受限时固定使用系统模式。

临时缓存与启动次数位于 `%TEMP%\eric\ericgamelauncher`。需要备份或转移配置时，可使用设置中的[配置导入导出](#backup)，无需手动整理文件。
</details>

<details>
<summary><b>卸载时能保留游戏库吗？</b></summary>

可以。在卸载确认页勾选“保留数据（设置、项目和图标）”，系统数据目录便会保留；默认不勾选，卸载时清理该目录。此选择作用于固定的系统数据目录，其他使用同一目录的副本也共享这份数据。游戏本体和其他解压副本的便携数据不在清理范围内。
</details>

<details>
<summary><b>支持 Windows 10 吗？</b></summary>

不支持。本项目基于 Windows App SDK 1.8 与 WinUI 3，需要 **Windows 11 24H2（Build 26100）** 或更高版本。
</details>

<details>
<summary><b>ARM64 电脑应该下载哪个版本？</b></summary>

下载同一份 x64 发行包即可，程序通过 Windows 11 的 x64 模拟运行。运行依赖也请选择 x64 版本，包括 .NET 10 运行时与 Windows App Runtime 1.8。
</details>

<details>
<summary><b>扫描没找到某款游戏，能手动添加吗？</b></summary>

可以，通过 **更多 → 添加** 选择游戏程序或快捷方式，也可填写平台协议、网页或商店应用入口。扫描依赖各平台的本机安装记录，扫描未发现游戏时可先确认对应客户端能正常识别它；不要仅凭扫描结果判断游戏已经卸载。使用平台协议启动时，本机需要安装对应客户端。
</details>

<details>
<summary><b>取消固定后，为什么任务栏里还能看到这款游戏？</b></summary>

普通游戏取消固定后，仍可能按启动次数出现在常用项目中。游戏平台取消固定后才会从平台组隐藏。可在项目属性中检查“这是个游戏平台”和固定状态，保存后等待任务栏列表刷新。清理临时缓存会重置对应的启动次数。
</details>
